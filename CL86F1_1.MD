# Claude Code Prompt: CRM loyalty badges + tier engine (portal.pandapatches.com)

Companion file: `claude-code-prompt-website-loyalty-promo.md` (website side).
Build the CRM side FIRST — the website promo validation calls the tier engine
built here.

## Program definition (owner-approved structure, Jul 28 2026)

Tiers by LIFETIME PAID order value (Square-confirmed payments only; unpaid /
cancelled / refunded orders excluded):

| Tier | Threshold | Benefits |
|---|---|---|
| **Bronze** | $1,000 | Badge + one-time 5% code, valid 90 days from award |
| **Silver** | $5,000 | Badge + standing 5% code + FREE Velcro backing (normally $30/order) + priority mockup queue |
| **Gold** | $10,000 | Badge + standing 10% code + one free rush upgrade per quarter + dedicated contact |

Rules:
- Tier is computed from lifetime paid value — it only goes UP, never down.
- Discounts apply to STANDARD CALCULATOR PRICING ONLY. Never stackable with
  custom/negotiated quotes, other promo codes, or sale prices. (This is the
  margin-protection rule — bulk customers already get negotiated pricing.)
- Codes are PERSONAL: tied to the customer's normalized email(s), unusable by
  anyone else. Bronze code is single-use; Silver/Gold codes are reusable but
  always email-bound.

## Task 1 — Tier engine (Supabase)

1. `loyalty_tiers` computation: on every payment-confirmed webhook event (and a
   nightly reconciliation job), recompute customer lifetime paid value using the
   same email-normalization the Data Manager exports use. Store on the customer:
   `lifetime_paid_value`, `loyalty_tier` (none/bronze/silver/gold),
   `tier_achieved_at` per tier.
2. `loyalty_codes` table: code (format PANDA-{TIER}-{6 random alphanum}),
   customer_id, tier, percent, single_use boolean, expires_at (Bronze:
   awarded+90 days; Silver/Gold: null), status, created/redeemed audit fields.
   Generate automatically on tier award.
3. Tier-award event → email to customer (from sales@, warm, short: badge earned,
   what it unlocks, their personal code; Bronze includes the 90-day expiry
   date). Near-threshold nudge email: when a customer comes within 20% of the
   next tier after a paid order, ONE email max per quarter ("you're $X away
   from Silver — here's what it unlocks").
4. Edge function `validate_loyalty_code(code, email, order_context)` → returns
   {valid, percent, tier, reason}. Enforces: email match, tier active, expiry,
   single-use, and order_context.pricing_source == 'calculator' (rejects
   custom-quote orders with reason "not combinable with custom quotes").
   Service-role only; this is the endpoint the website form calls server-side.

  `priority_mockup` flag surfaced in the production/design queue view.
- Gold quarterly rush upgrade: `rush_upgrades_used` counter per quarter;
  builder shows availability; using it zeroes the rush fee for that order and
  decrements. Resets quarterly.

**Follow-up chain & suppression rules:**
- Award emails (E1–E3) are transactional: always send, once, idempotent.
- E4 fires only if the Bronze code is unredeemed; never more than once.
- E5: max 1/quarter per customer, only after a PAID order, skip if the
  customer had a complaint/remake open in the last 30 days, and include an
  unsubscribe that suppresses E5 only (never suppresses transactional E1–E3).
- Global cap: no customer receives more than one loyalty email in any 14-day
  window (transactional award wins if two collide; queue the other).
- Every send logged (customer, template, timestamp) for the Reports metrics.
- NO review asks anywhere in these emails (review program is separate).

## Guardrails
- Actual PAID amounts (post-discount) flow to Square, the Data Manager order
  export, and Google Ads value upload — never pre-discount values.
- No changes to the frozen export views, GTM, or conversion wiring.
- Refunds reduce lifetime_paid_value on reconciliation, but a tier once
  awarded is not clawed back automatically (flag for manual review if a
  customer drops below threshold via refunds).
- Emails: transactional tier notifications only from this system; marketing
  cadence stays in Zoho Campaigns. No review asks in these emails.
